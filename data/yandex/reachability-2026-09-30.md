# Доступность bixbit.io из РФ — 2026-09-30

> **Контекст (со слов команды, 2026-09-30):** bixbit.io заблокирован в РФ решением суда (РКН), российская аудитория ходит на bixbit.tech. Результаты ниже — следствие блокировки. Рекомендации «найти правило файрвола» и «включить прокси Cloudflare» **отменены**.

Источник: check-host.net (узлы RU/KZ/MD/NL/PL/TR/UA/US), собственные проверки DNS/TLS. Причина — Яндекс.Вебмастер `FATAL CONNECT_FAILED`.

## DNS
- `bixbit.io` → A `129.212.254.154` (DigitalOcean, **напрямую, без прокси Cloudflare**), AAAA нет.
- `www.bixbit.io` → Cloudflare (104.21.93.194, 172.67.214.47 + IPv6), отдаёт 301 на apex.
- NS: Cloudflare (eric / kristin).
- `docs.bixbit.io` → GitHub Pages.

## TLS (129.212.254.154:443)
Сертификат `*.bixbit.io`, Sectigo OV R36 → Root R46 → USERTrust, действует с 26.06.2026 по 10.01.2027. Цепочка полная, TLS 1.2/1.3, без SNI отдаётся тот же сертификат. **Не причина.**

## Вывод
Из России не устанавливается TCP-соединение с origin-сервером `129.212.254.154` ни на 80, ни на 443. Остальные страны подключаются без проблем. Ping с одного московского узла проходит, значит пакеты до сервера доходят, а TCP отбрасывается. Это типично для правила файрвола (DO Cloud Firewall, ufw/iptables с geoip, fail2ban/CrowdSec). Блокировку на российской стороне тоже нельзя исключить: точно это покажет `tcpdump` на сервере (см. dev-task P0-0). Хосты за Cloudflare (www) и GitHub (docs) из России доступны.

Эта же причина объясняет сигнал `NO_ROBOTS_TXT` и то, что sitemap не забирается с 06.08.
